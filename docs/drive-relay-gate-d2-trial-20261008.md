# Gate D2 synthetic trial harness

Status: **TRIAL / repository preparation only**. This artifact does not authorize deployment, Drive configuration, public write activation, patient/clinic data, or production adoption.

`app/drive-relay-d2-trial.html` is unlinked and `noindex,nofollow`. It accepts only its own prepared `?bridge=` URL, validates it, and has one IndexedDB state record. The iPad creates only its stable, non-extractable ECDSA sender key and high-entropy bearer; the lab PC owns the recipient private key. The bridge supplies only `{recipientKeyId, publicJwk}`. Existing package, crypto, receiver-bootstrap, and transport builders create a tiny synthetic package.

The parent uses an HtmlService iframe bridge because ContentService CORS is not assumed. Every message binds to iframe `contentWindow`, a random per-page channel, and one observed exact origin. Apps Script may redirect the exact `script.google.com` deployment to `https://script.googleusercontent.com`; those are the only two accepted origins, and once the ready message is observed the response must remain at that exact origin. Arbitrary `*.googleusercontent.com` origins are not accepted. The bridge requires the exact configured parent origin. The repository Apps Script source is inert unless `D2_TRIAL_ENABLED=true` and `D2_PARENT_ORIGIN`, `D2_SYNTHETIC_ROOT_ID`, `D2_RECEIVER_BEARER_SHA256`, and `D2_RECIPIENT_PUBLIC_JSON` are configured. Pairing additionally needs `D2_PAIRING_ENABLED=true`; it stores a hash-only upload verifier and root `pairing.json` public sender registry, then closes pairing.

Drive uses opaque job/object names, hashes/sizes/bootstrap metadata, `meta.json`, and a ready marker written last. Before the first ciphertext write, the server records a root-level opaque staging commitment containing the descriptor, full object layout, bootstrap binding, and plan hash; a partial retry must match it exactly, so a different layout cannot attach to the same job ID. No work-order reference, names, source filenames, or plaintext payload are stored. The adapter rejects absent/hash- or size-mismatched Drive-for-desktop objects before decrypt, persistence, or ACK; it loads the separate root pairing registry rather than trusting a job key. It invokes ACK only after verified persistence. ACK permanently deletes exact direct-child IDs only, with `ready -> deleting` retry state and no Trash.

Setup/run boundary: use a dedicated synthetic Drive root; create a separate Apps Script deployment manually; set only synthetic values; prepare one GitHub Pages URL with `?bridge=`; enable pairing for one browser pair; then disable it. Send only the built-in tiny synthetic fixture. The PC may be offline; no background service is introduced. Cleanup is a separate authorized operation: disable `D2_TRIAL_ENABLED`, remove synthetic deployment/configuration, and permanently remove only the dedicated synthetic root after confirming it contains no wanted data.

For one explicit lab-PC trial run (not a daemon), invoke `node gateway/drive-relay-d2-adapter.mjs --config=<synthetic-config.json>`. The config contains only paths and the Apps Script endpoint; the synthetic receiver bearer and recipient-backup passphrase must be supplied through `D2_RECEIVER_BEARER` and `D2_RECIPIENT_BACKUP_PASSPHRASE`. Node fetch follows the Apps Script `ContentService` redirect. The command prints only a status/error code, never either secret or work-order content.
