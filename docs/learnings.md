# Learnings

このファイルは、デジタル歯科技工指示書リポジトリでの作業を通じて得られた
ルール・再発防止事項・判断保留事項を記録する。

## 位置づけ

- 業務仕様・画面仕様の正本は `docs/design.md` である。ここに業務仕様を重複記載しない。
- 恒久的な作業ルールは `AGENTS.md` / `AGENTS.local.md` に置く。このファイルは、
  そこに昇格させる前の記録・再発防止・判断保留を扱う。
- AIはこのファイルを自動更新しない。AIは改善候補を提示し、人間承認後にのみ追記・修正する。

## 個人情報禁止ルール

- 患者名、医院名、症例詳細、請求情報、その他の秘密情報・個人情報はこのファイルに記録しない。
- 記録が必要な場合も、一般化・匿名化した形でのみ記載する。

## 確定した業務・開発ルール

### 2026-08-19: Learning Gate と非エンジニア向け危険説明

人間承認済みの学習として、以下をこのrepositoryの恒久的な作業ルールへ反映する。

- ユーザーからAIの進め方・安全判断・役割分担・説明方法への訂正を受けた場合、学習候補として評価する。
- 同種の失敗や回避可能な混乱が繰り返された場合、新しい安全ルールや再利用可能な改善が見つかった場合も学習候補として評価する。
- 重要な候補は発見時に提示し、セッション終了時には未解決候補を最大3件まで提示する。
- 学習候補は「発動条件」「学習内容」「残す理由」の3点で示す。
- 人間の承認前に自動保存・自動昇格しない。
- 非エンジニアへ技術判断を求める前に、「何が起こり得るか」「今止めるべきか」「人間に必要な判断は何か」を平易な言葉で説明する。
- 単発の実装詳細は恒久ルール化せず、再利用可能で一般化できる学びだけを残す。

このルールの実行条件は `AGENTS.local.md` の `Learning Gate` を正本とする。

### 2026-08-19: 技術監査と人間判断の境界

人間承認済みの学習として、以下を恒久的な作業ルールへ反映する。

- コード差分、テスト、Git状態、仕様整合性、技術的な危険性など、専門知識が必要な確認はAI側で完結して判定する。
- AIが判断できない技術事項は、人間へ丸投げせず `UNKNOWN` として理由を説明する。
- 人間へ求める確認は、業務意図、実機の見た目・操作感など人間にしか判断しにくい事項、およびmerge・削除など高リスク操作の最終許可に限定する。
- 最終監査は `PASS` / `NG` / `UNKNOWN` を先に示し、その後に「人間が判断する必要が残っている点」だけを平易に提示する。
- 技術資料や監査証拠はAIの判断根拠として保持するが、人間が理解しなければ承認できない宿題として提示しない。

このルールの実行条件は `AGENTS.local.md` の `Human Decision Boundary` を正本とする。

## 再発防止

### 2026-08-17: 役割・自動フローの推測による取り違え

以下の事象が発生したため、再発防止事項として記録する。

- 既に確立されている自動フローを、会話中に勝手に「手動案内」に置き換えて案内した。
- Codex と Claude の担当領域を推測で取り違えた。
- GPT の GitHub 上の操作範囲（PR監査・merge管理）と、
  PCローカルでの操作範囲（実装・ローカルGit操作）を混同した。

再発防止事項:

- 既存の自動フローを勝手に手動化して案内しない。
- Codex / GPT / Claude の担当を推測で取り違えない。
- GitHub上の操作とPCローカル操作を混同しない。
- 作業開始時に、現在の役割分担と `docs/session-handoff.md` を確認する。
