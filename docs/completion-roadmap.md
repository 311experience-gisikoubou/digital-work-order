# Project Completion Roadmap

## 目的

この文書は、デジタル歯科技工指示書を「何ができれば完成とするか」と、残件の必要性を短く管理する。
業務・画面仕様の正本は `docs/design.md` のままとし、ここでは完成条件と残件分類だけを扱う。

## 主目的

iPad Safari + Apple Pencil を主利用環境として、歯科技工指示書の入力、手書き、PDF/印刷、紙指示書の安全なローカル取込補助、技工所内の後続受注連携までを一貫して扱う。

## 完成条件

1. iPad Safariで医院側入力、受注管理、手書き、歯式・クラスプ、PDF/印刷の主要フローが成立する。
2. 紙指示書は外部OCR/AIへ送らず、ブラウザ内の一時画像・ローカルOCR・人間確認・安全な破棄で扱える。
3. 一時受注は同一タブ再読み込みから安全に復元し、未知/不正データはfail closedにできる。
4. `workOrderRef` を維持したローカルJSONで、納品・請求管理アプリへ明示的に引き渡せる。
5. 患者・医院・受注情報について、未承認の外部クラウド保存・外部AI送信を追加しない。
6. 利用者へ案内する通常の入口が、監査済みの現行版と一致している。
7. 上記の主要フローを、架空データによる自動テスト・ブラウザ確認で再現でき、AI側で客観確認できない主観的な見た目・業務・仕様判断だけを人間確認へ残す。


## 人間確認境界

表示値、DOM/画面構造、保存・復元結果、公開内容の一致など、AIが機械的・客観的に確認できる項目は人間確認ポイントにしない。人間確認を残すのは、見た目の好み、業務上の選択、仕様の採否、または機械的に判定できない実機の主観的操作感に限る。

## A項目の証拠と次工程

2026-09-13の読み取り確認では、公開GitHub PagesはHTTP 200で存在する一方、最新deployは2026-08-11の `claude/redesign-dental-form-qG3Ue` / `5fea9c3...` だった。公開HTMLにも現行mainの `dwo_session_orders_v1`、`dwo_session_active_tab_v1`、`workOrderRef` が確認できず、旧Firebase表現が残っていた。

したがって次の完成必須タスクは、**既存のGitHub Pagesという同じ配布経路を再利用し、公開入口を監査済みcurrent mainへ揃えたうえで、架空データだけで公開URLの表示値・画面構造・主要フローをAI側で客観確認すること**とする。新しいhosting serviceは追加しない。客観確認できる項目のためだけに人間確認は追加しない。

このA項目を解消した後、現在確認できている完成必須A項目は0件になる見込み。解消後に再棚卸しし、A=0なら本ロードマップの主目的に対して完成判定へ進む。
