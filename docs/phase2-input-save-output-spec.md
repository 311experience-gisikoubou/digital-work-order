## 3. データの役割を分ける

### 3.1 編集中フォーム

- 画面上の入力値、歯式、クラスプ、手書き、座標を編集中の状態。
- 「下書き保存」で端末内へ保存する。
- 保存キーは新規の `dwo_form_draft_v1` 1個に限定する。
- メディア本体をlocalStorageへ入れない。PR #120を再利用する場合、メディアはOPFS、metadataはIndexedDBの既存案を使う。
- 下書きとメディアで別々のdraft IDを作らず、同一の `draftRef` を共有する。

### 3.2 発行済み受注

- 発行時点の論理入力と表示用snapshotを固定する。
- stable `workOrderRef` は発行時に1回だけ生成し、再PDF・納品JSON出力で同じIDを使う。
- 現行 `state.orders` と同一タブ `sessionStorage` の受注管理は維持する。
- Phase 2で発行済み受注の新しい長期DBは作らない。将来の技工所PC転送は既存メディア転送ロードマップの責務とする。

## 4. 下書き保存

### 4.1 保存対象

下書きは、発行時に必要となる入力を「再開可能な形」で保存する。

- 患者・医院情報
- 発行日、模型発送予定日、納期、次回予約
- 保険/自費、優先度
- 発注形態、修理詳細
- 補綴物、床、クラスプ、バー、数量、各詳細
- 人工歯、色調
- 対合歯、バイト、GoA、咬合器
- 備考
- 32歯の歯状態
- クラスプ配置
- 歯式側手書き、メモ側手書き
- 歯式座標
- メディアのownerとなる `draftRef`

### 4.2 保存しないもの

- Object URL
- Blob本体
- DOM HTML
- PDF Blob
- OCR一時画像・OCR候補
- 通知/ユーザー名など採用レイアウト内の表示サンプル

### 4.3 復元

- 起動時、`dwo_form_draft_v1` が存在すればschemaを厳格検証する。
- schema不正・未知version・不正型の場合は**部分復元しない**。
- 不正データを現在フォームへ混ぜず、復元できなかったことを表示する。
- 正常な下書きはフォーム、歯式、クラスプ、手書き、座標を同じsnapshotから復元する。
- 下書きは**発行成功または明示的な「下書きを破棄」操作**で削除する。自動期限切れで黙って消さない。
- 端末内に患者・医院情報を含む下書きが残ることをUIで短く明示する。共有端末では利用者が明示破棄できるようにする。
- localStorageが利用できない場合は保存成功扱いにせず、現在画面の入力を保持したまま保存失敗を表示する。
- `dwo_drawing_v1` と `dwo_clasp_v1` は既存互換のため維持し、Phase 2で削除・破壊しない。

## 5. 歯式の単一状態

### 5.1 正本

各FDI歯番号の状態は次の2軸を正本とする。

- `baseState`: `normal | missing | abutment`
- `caution`: `true | false`

これにより、欠損と支台歯は同時成立せず、要注意だけ独立して重ねられる。

### 5.2 既存互換

- 既存 `state.selectedTeeth` は「欠損歯集合」として当面維持する。
- `baseState === "missing"` の歯番号から `selectedTeeth` を派生させる。
- 図・数字・拡大表示は同じ歯状態を参照し、別々の真実を持たない。
- 既存座標32歯とFDI番号は canonical JSON を再利用する。
- 小型の上顎/下顎プレビューと数字歯式、拡大画面で同じ状態を共有する。

### 5.3 クリア

- 対象歯のクリアは、その歯だけを `baseState=normal`、`caution=false` に戻す。
- 全歯リセットは対象歯クリアとは別操作として扱う。
- 座標修正は歯状態とは別で、欠損/支台歯/要注意を消さない。

## 6. 発行フロー

「この内容で発行する」は次の順番で処理する。

1. 現在フォームを収集する。
2. 既存必須4項目を検証する。
3. 歯式・クラスプ・手書き・座標を含む `visualSnapshot` を固定する。
4. 模型発送予定日・営業日数・標準納品日・急ぎ料金を現在の既存計算結果から固定する。
5. secure `workOrderRef` を1回生成する。
6. 既存B5/A4用紙選択を表示する。キャンセル時は発行しない。
7. **固定済み受注snapshotから**PDF Blobを作成する。
8. 添付がある場合、PR #120の方式を再利用して同じ `draftRef` から `workOrderRef` へ紐付ける。保存不能・不整合はfail closedとする。
9. `state.orders` へ受注を追加し、既存session保存を同期する。
10. 発行成功後に `dwo_form_draft_v1` を削除し、フォームを初期化する。
11. 作成済みPDFを表示する。

PDF作成、添付紐付け、必須検証のいずれかが失敗した場合は「発行完了」と表示せず、入力・下書きを消さない。

## 7. 受注ごとの表示snapshot

現行はPDFが「現在画面の歯式/クラスプ」を参照し得るため、発行済み受注ごとに固定snapshotを持つ。

`visualSnapshot` に最低限含めるもの:

- 32歯の `baseState/caution`
- 互換用 `selectedTeeth`
- `claspState` のdeep copy
- 歯式図側 `drawStrokes`
- メモ側 `memoStrokes`
- 32歯の座標

PDF、詳細、再印刷は対象受注のsnapshotから描画する。他受注や現在編集中のグローバル状態を借りない。

旧受注に `visualSnapshot` が無い場合、現在画面の図を代用してはならない。旧形式で確実に存在する文字データだけを表示し、存在しない図情報は「情報なし」として扱う。

## 8. PDF仕様

- B5 182×257mm、上下2面を維持する。
- A4は現行どおりB5内容を中央配置し、B5内容自体を拡大しない。
- 1件印刷は下段空白、2件印刷は各受注を独立snapshotで描画する。
- 歯式番号欄は**8–8**として 18/28/38/48 を含める。既存歯式ブロック外寸は変えず、ブロック内部だけを調整する。
- 欠損だけでなく、支台歯・要注意もPDFで判別できる状態表示を行う。歯形態そのものは描き直さない。
- `shippingDate` を「模型発送予定日」として表示する。
- `expediteFeeYen` が0なら「急ぎ料金 なし」、0超なら金額を表示する。
- 急ぎ料金はPDF用に再計算せず、発行時に既存 `applyDelivery()` と同じ結果をsnapshotする。
- 休日判定、保険11営業日、自費14営業日、既存急ぎ料金計算式は変更しない。
- 修理詳細は既存確定どおり備考先頭へ反映し、二重表示しない。
- メディア本体はPDFへ埋め込まない。

## 9. 納品・請求アプリ連携JSON

- `digital-work-order-intake-v1` と stable `workOrderRef` を維持する。
- 納品・請求アプリ側のDB・請求業務を本Repoへ重複実装しない。
- 既存v1出力を壊さないため、Phase 2の新規snapshotは直ちに既存schemaへ強制追加しない。
- 下流で必要性が確認された項目だけ、別versionまたは後方互換の拡張として扱う。
- 受注の欠損歯互換出力 `sourceTeeth` は `baseState=missing` から生成した `selectedTeeth` を引き続き使う。

## 10. PR #120との境界

- PR #120は**未マージ**であり、main実装として数えない。
- Phase 2では、そのOPFS/IndexedDB・fail-closed・draft→workOrderRef再紐付け設計を再利用候補とする。
- フォーム下書きの `draftRef` とメディアのactive draftを一本化する。
- PR #120を取り込むときは最新mainへrebase/再適用相当の整合確認を行い、過去の140 PASS/16 checksを現在HEADのテスト証拠として再利用しない。
- 添付のない受注はメディア機能の有無で発行不能にしない。
- 添付があるのに安全な永続化ができない場合は、黙って添付を落とさず発行を止める。

## 11. 非対象

Phase 2では次を実装しない。

- 技工所PCへの送信完了
- クラウド中継
- 暗号・署名・鍵管理
- 新しい認証/ログイン/通知基盤
- 発行済み受注の新規長期DB
- 納品・請求アプリ機能の複製
- OCR対象項目の拡張
- 備考500文字制限の新設
- 歯形態の描き直し

## 12. 実装時の合格条件

- 既存4必須項目を満たさない発行は従来どおり拒否する。
- 下書き保存 → タブ/ブラウザ終了 → 再起動 → 復元が架空データで成立する。
- 欠損/支台歯排他 + 要注意併存が図・数字・拡大・発行snapshotで一致する。
- 2件印刷で各受注の歯式/クラスプ/手書きが混ざらない。
- PDFに8番歯、模型発送予定日、急ぎ料金が反映される。
- B5上下2面の外形、既存休日判定、既存料金式、既存localStorage 2キー、既存delivery-intake-v1を壊さない。
- 添付あり/なし、保存不能、不正metadataで黙ったデータ欠落を起こさない。
- 自動確認可能な項目を人間確認へ戻さず、iPadの主観的な見た目/操作感だけを最終実機確認へ残す。
